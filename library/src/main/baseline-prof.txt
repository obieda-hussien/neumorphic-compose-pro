# Baseline profile for composeNeumorphism (human-readable format).
#
# WHAT THIS IS: a hand-authored starting profile listing the library's
# always-hot internal classes (the blur/cache/config machinery that runs on
# essentially every neumorphic draw). Bundling it in the AAR means AGP
# automatically merges it into any consuming app's own baseline profile at
# build time - no setup required on the consumer's end beyond depending on
# this library normally.
#
# WHAT THIS IS NOT: this file only contains class-level rules (plain
# "Lpackage/Class;" lines), which tell ART "expect this class to be used
# early, preload/verify it ahead of time." It deliberately does NOT contain
# method-level H/S/P rules (e.g. "HSPLpackage/Class;->method(...)V") for the
# neumorphic()/animatedNeumorphic()/springNeumorphic() composable functions,
# because Compose's compiler generates synthetic default-argument dispatch
# methods and mangled internal names for those - guessing their exact JVM
# signatures by hand without access to the compiled .class files would very
# likely produce wrong/unmatched rules. Class-level rules don't have that
# problem, since they only need the class's own fully-qualified name.
#
# For a more complete, precise profile (including the hot composable
# entry points), generate one from a real device/emulator using the
# Macrobenchmark + Baseline Profile Gradle plugin against the demo app,
# then merge its relevant lines in here. See:
# https://developer.android.com/topic/performance/baselineprofiles/overview
