# 5.0.0 rendering engine

The Compose built-in renderer uses a DrawModifierNode. It renders cached masks only;
a cold miss draws content without a shadow. The last ready configuration can be used
while a replacement is generated, provided its geometry size matches and its masks
remain cached. There is no unbounded per-node bitmap retention.

## Generation

Requests capture geometry (including custom Compose paths), density and immutable
render settings. The same settings drive cache identity and blur sampling, even if
battery or application policy changes while a worker is running. Identical requests
share work. At most two workers execute and at most 64 distinct requests are pending.
A 16ms settle interval coalesces animation changes. A detached subscriber cancels its
wait; shared work continues only while another subscriber needs it. Pending work without
subscribers is cancelled so offscreen rows do not occupy the queue. Only the current request may
publish. Requests above the queue bound use the content-only fallback and retry up to three times
with increasing delays; later UI invalidations may also retry. This is bounded degradation, not a promise of immediate shadows.

Visibility follows Compose node attachment; explicit prefetch and scheduler priorities
are not yet exposed. Custom NeuShape implementations should implement resolveCorners
and honor allowSynchronousGeneration if they do their own drawing.

## Cache and resource ownership

A single byte budget covers probation and protected entries. Repeatedly used entries
are evicted after probation entries, but cannot exceed the same budget. Eviction does
not recycle a bitmap that a renderer may still reference. Temporary source masks are
released after generation. Oversized masks are not admitted. Backend render targets
and caller-owned bitmaps are separate from cache accounting. GPU sessions have an additional
16 MiB estimated buffer budget (three RGBA buffers per target), and at most six exact-size targets.

UI_HIDDEN releases backend resources independently of RUNNING_CRITICAL. Memory pressure
reduces the cache budget; explicitly reassign shadowCacheBudgetKB to restore it.

## Backends

API 31+ uses exact-size RenderEffect sessions; API 24–30 uses RenderScript with StackBlur
recovery. RenderEffect currently reads back software pixels. Automatic hardware bitmap
promotion is disabled to avoid immediately uploading the readback again. This is not a
zero-copy GPU renderer and GPU speed is not assumed. Validate on physical devices.

## Public diagnostics

NeuPerfStats.snapshot() exposes cumulative cache hits/misses, cache bytes and budget,
pending requests, average worker duration and failures, preferred backend, thermal tier
and power-save state. The preferred backend label does not claim a fallback never ran.
The demo additionally measures FrameMetrics.TOTAL_DURATION P95/P99 over 600 samples.

## Verification

CI runs instrumented tests on API 24, 29 and 34, and macrobenchmark smoke tests on 29
and 34. The stress scenario opens an explicit 300-row screen with fast swipes.
Use scripts/compare-benchmarks.py with baseline and candidate JSON from the same device
for a regression gate. Emulator timing is a smoke signal, not a product performance claim.
